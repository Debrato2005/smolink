## Local infrastructure

### `docs/docker-compose.yml`

`services` contains PostgreSQL and Redis. PostgreSQL uses `postgres:16-alpine`.
Its initialization values create the `smolink` user and database on first
startup. Host port `5432` maps to container port `5432`. The named
`postgres_data` volume mounts at `/var/lib/postgresql/data`.

The PostgreSQL health check runs `pg_isready -U smolink -d smolink` through
`CMD-SHELL`. It checks whether the server accepts connections. It does not
verify credentials or application queries. The check runs every five seconds,
with a five-second timeout and five retries.

Redis uses `redis:7-alpine` and starts with `--appendonly yes`. Host port
`6379` maps to container port `6379`. The named `redis_data` volume mounts at
`/data`. `CMD` runs `redis-cli ping` without a shell. Timing matches the
PostgreSQL health check. Both named volumes appear under `volumes`.
The named volumes retain local files when containers are recreated. Removing
the volumes can remove those files. Other Compose containers resolve the
PostgreSQL service as `postgres`; the host-run backend uses the mapped port.

Volume persistence does not make Redis authoritative. PostgreSQL owns durable
application data. Use `-f docs/docker-compose.yml` in root-level Compose
commands. The [development guide](development.md) contains the procedure.

The 2026-07-19 connectivity checks returned `1` for PostgreSQL `SELECT 1` and
`PONG` for Redis. These are historical availability observations. The current
application Redis client exists in `core/redis.py`.

### `backend/pyproject.toml`

`[project]` defines package name `backend`, version `0.1.0`, the Smolink
backend description, and Python requirement `>=3.13`. Package version and
`/api/v1` are separate version identifiers.

Runtime dependencies cover FastAPI/Uvicorn, Pydantic settings, async
SQLAlchemy/asyncpg, Alembic, Redis, Argon2id, PyJWT, HTTPX, QR generation, and
user-agent parsing. Installed QR and user-agent packages do not imply that
QR or analytics endpoints exist.

`[tool.fastapi]` sets `entrypoint = "app.main:app"`. The CLI imports `app` from
`app/main.py`. The development dependency group includes `httpx`, `pytest`,
and `pytest-asyncio`. HTTPX is also a runtime dependency for email delivery.
`uv.lock` records resolved versions. Do not edit it by hand.

## Application and configuration

### `backend/app/main.py`

The module imports `FastAPI` and the versioned router. `create_app()` creates
an application with title `smolink` and version `0.1.0`. These values appear in
OpenAPI metadata. `include_router(..., prefix="/api/v1")` mounts URL and auth
routes. The inline `/health` handler returns `{"status":"ok"}`.

`return app` returns the configured instance. Module-level `app=create_app()`
exposes it to the CLI and Uvicorn. The factory does not register global domain
exception handlers. `endpoints/health.py` remains empty because the handler
is still inline. Commented tutorial code has no runtime effect.
The `BaseModel` import is also commented out. Removing the tutorial material
remains an unchecked foundation-cleanup task.

`@app.get("/health")` registers the following function for `GET /health`.
The return annotation `dict[str, str]` describes string keys and values.
FastAPI serializes the returned dictionary to JSON with default status `200`.
An application factory also gives tests a place to create separate configured
instances when needed.

Both `uv run fastapi dev app/main.py` and
`uv run uvicorn app.main:app --reload` import this instance. The latter is a
development command, not a production command.
`app.main:app` selects the module and its exported variable. Importing the
module executes the factory call. Uvicorn then serves the application through
the Asynchronous Server Gateway Interface (ASGI).

### `backend/app/api/v1/router.py`

The module creates an `APIRouter`, then includes the URL and auth routers.
Their prefixes supply `/urls` and `/auth`. It does not mount redirects,
owned URL management, QR routes, analytics, or Google routes.

### `backend/app/core/config.py` and `.env.example`

`Settings` inherits Pydantic `BaseSettings`. Fields without defaults are
required. Environment names map to field names, such as `DATABASE_URL` to
`database_url`.

| Configuration | Meaning |
|---|---|
| `DATABASE_URL` | SQLAlchemy connection URL. The template uses asyncpg and local port `5432` |
| `REDIS_URL` | Local Redis connection. The template uses database `0` |
| `JWT_SECRET`, `JWT_ISSUER`, `JWT_AUDIENCE` | Token signing and claim validation |
| `ACCESS_TOKEN_TTL_SECONDS`, `REFRESH_TOKEN_TTL_SECONDS` | Required lifetimes. The template uses `900` and `2592000` seconds |
| `TOKEN_HASH_SECRET` | Key for refresh-identifier and opaque-token hashes |
| `IP_HASH_SECRET` | Key for planned click IP hashing |
| `PUBLIC_BASE_URL` | Base for returned short URLs. The template uses `http://localhost:8000` |
| `REDIS_CACHE_TTL_SECONDS` | Planned cache lifetime. Default `3600` |
| `SNOWFLAKE_WORKER_ID` | Generator worker value. Default `0` |
| `APP_PUBLIC_URL` | Frontend email-link base. The template uses `http://localhost:3000` |
| `EMAIL_FROM`, `RESEND_API_KEY` | Sender identity and Resend credential |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` | Required configuration for the unfinished Google flow |

`SettingsConfigDict` selects `.env`, UTF-8, and `extra="ignore"`. The file path
is relative to the process working directory. Run the backend from `backend/`.
Unrelated `.env` variables do not cause validation failures.

`@lru_cache` stores the first `get_settings()` result. Later calls reuse that
object. Environment changes do not replace an already cached instance.
Keep local secrets in the ignored `.env` file. The template contains safe
local credentials and secret placeholders, not usable production secrets.

## Database

SQLAlchemy supplies object-relational mapping (ORM). Its mapped classes
represent database tables and records.

### `backend/app/db/session.py`

The module imports async SQLAlchemy types and loads cached settings.
`create_async_engine(..., pool_pre_ping=True)` creates the shared engine.
Pre-ping checks pooled connections before reuse. The engine uses the driver
specified by `database_url`.

`async_sessionmaker(..., expire_on_commit=False)` creates sessions whose loaded
attributes remain available after commit. `get_session()` opens one session
with `async with`, yields it, then closes it after dependency use. The session
is shared within a request. It must not be shared across concurrent requests.
Closing an uncommitted session rolls back its pending transaction.

### `backend/app/db/base.py` and `models/__init__.py`

`Base(DeclarativeBase)` supplies shared SQLAlchemy metadata. Concrete models
inherit from it. `models/__init__.py` imports all eight models to register
their tables. Alembic imports that package explicitly. `db/base.py` does not
itself import every model.

### `backend/alembic/`

`alembic.ini` sets the script directory and retains a placeholder connection
URL. `env.py` replaces that URL with `get_settings().database_url` at runtime.
It imports models and assigns `Base.metadata` to `target_metadata`.

Online migration uses an async engine with `NullPool` and
`connection.run_sync(...)` for Alembic's synchronous operations. Offline mode
configures literal binds without a live connection. The revision chain is:

1. `10e6aa664dee`: initial users, URLs, and click events.
2. `3fa3b9fcf564`: auth user fields and identities.
3. `23292c5cb33d`: refresh, verification, reset, and OAuth-request tables.

A 2026-07-20 check found no revision before the initial migration existed.
That result is historical. Use `uv run alembic current` for local state.
Applied migrations remain unchanged during this prose refactor.

### Models

- `user.py`: `users` has a Snowflake `BIGINT` ID, unique indexed email, nullable password hash, timestamps, verification time, lock state, and `auth_version`.
- `url.py`: `urls` has a separate numeric ID and public `short_code`, a destination, nullable owner and expiry, click aggregates, and timestamps.
- `click_event.py`: `click_events` has a URL reference, click time, browser, operating system, device, optional referrer, and keyed IP hash.
- `auth_identity.py`: `auth_identities` links a provider/subject pair to a user. The pair is unique and the user reference is indexed.
- `refresh_token.py`: `refresh_tokens` stores a keyed `jti` hash, family UUID, parent reference, issued/expiry times, and use/revocation times.
- `email_verification_token.py`: hashed opaque verification token, user, expiry, and consumption time.
- `password_reset_token.py`: hashed opaque reset token, user, expiry, and consumption time.
- `oauth_authorization_request.py`: hashed state, nonce, raw PKCE verifier, expiry, consumption time, and creation time for future Google authorization.

Deleting a user sets URL `owner_id` to `NULL`. Auth child rows cascade on user
deletion. Deleting a URL cascades to its click events. The click index combines
`url_id` and `clicked_at`. Click rows have no raw IP or raw user-agent field.

`short_code` is `String(64)` and stores generated codes or aliases. Destination
strings allow 2048 characters in the model. `total_clicks` is an `Integer` with
default `0`, not `BIGINT`. SQLAlchemy emits `func.now()` for `updated_at` when
its update expression applies. There is no database trigger for arbitrary
external SQL updates.

## URL creation

### Utilities

`base62.py` uses digits, lowercase letters, then uppercase letters.
`encode_base62(0)` returns `"0"`. Negative values raise `ValueError`.
`divmod` returns the quotient for the next iteration and the remainder for
an alphabet index. Remainders `1` and `36` select `"1"` and `"A"`.

`snowflake.py` combines elapsed milliseconds, a 10-bit worker ID, and a 12-bit
sequence. `(1 << n) - 1` computes the largest value in `n` bits. Worker IDs
range from `0` to `1023`. A generator permits 4096 sequence values per
millisecond before waiting for the next millisecond.

A lock protects one generator instance. A backward clock raises an exception.
`CUSTOM_EPOCH_MS` is `17_893_456_123`, which corresponds to
`1970-07-27T02:24:16.123Z`, not January 2026. Keep the value stable after ID
issuance. The code does not enforce a 41-bit elapsed-time bound.

The auth and URL route modules currently create separate generators with the
same worker ID. Their sequence state is independent. IDs can collide if both
generate the same sequence within one millisecond. Multi-instance deployment
also requires distinct worker IDs. These are coordination requirements, not
uniqueness guarantees established by the current tests.

`aliases.py` lowercases input and accepts 3–64 lowercase letters, digits, or
hyphens. Reserved names include root routes and legacy auth names. Both
aliases and generated codes occupy `urls.short_code`.

### Schemas, repository, service, route

`CreateUrlRequest` validates `destination` with Pydantic `HttpUrl`. It carries
optional `alias` and `expires_at` fields. `CreateUrlResponse` returns ID,
code, short URL, destination, expiry, and creation time. `from_attributes=True`
allows attribute-based model conversion.

`url_repository.py` inserts with `session.add()` and `flush()`. Lookup uses
`select(Url)` by `short_code` and `scalar_one_or_none()`. It does not commit.

`create_short_url()` rejects a non-future expiry, generates an ID, and selects
an encoded code or normalized alias. An existing alias raises
`AliasTakenError`. A valid model carries the supplied nullable `owner_id`.
The repository flushes that model.

The route applies optional authentication and its matching creation limiter.
It commits the created URL, refreshes generated fields, and returns `201`.
Guest requests store no owner. Authenticated requests store the user's ID.

`InvalidAliasError` and `InvalidExpiryError` map to domain envelopes with `422`.
Alias conflicts map to `409 alias_taken`. A database error rolls back. The
route maps SQLSTATE `23505` to the same conflict response and re-raises other
database failures. It builds `short_url` from `PUBLIC_BASE_URL`.

## Rate limiting

`core/redis.py` caches a Redis async client. It does not establish a production
shutdown procedure. Test fixtures replace this client to keep connections in
the event loop that created them.

`core/rate_limit.py` defines the Lua script, frozen `RateLimitResult`, and
`SlidingWindowRateLimiter`. The script removes scores through the window
cutoff, counts remaining members, and rejects at the limit. An allowed request
adds a unique timestamp/UUID member and resets key expiry atomically.

`check()` uses an explicit `now_ms` when supplied, including zero. Otherwise
it reads the current clock. It converts seconds to milliseconds for Redis.
On denial, it calculates the oldest member's remaining lifetime in seconds,
rounds upward, and returns at least `1`. Allowed results have `retry_after=0`.

The dependency chooses `rate:create:guest:{ip}` at 10 requests or
`rate:create:user:{user_id}` at 30 requests per rolling minute. Auth POST
routes share `rate:auth:{ip}` at 5 requests per rolling minute. IP extraction
uses `request.client.host`, with `"unknown"` for no client. It does not parse
forwarded headers. Denial returns `429` with `Retry-After`. Any limiter
exception maps to `503`. These dependency errors use FastAPI's `detail` body.

## Local authentication

### `utils/security.py` and `schemas/auth.py`

Security helpers normalize email with `strip().lower()`, hash and check
passwords with Argon2id, create random opaque tokens, sign and validate JWTs,
and compute keyed HMAC-SHA256 token hashes. Signing does not encrypt a JWT.
Its header and claims remain readable.

The JSON Web Token (JWT) helpers validate issuer, audience, expiry, token type,
and required claims. Access claims include `sub` and `auth_version`. Refresh
claims include `sub`, `jti`, and `family_id`. Refresh records hash `jti`, not
the complete token. Opaque verification/reset records hash the complete opaque
value. Neither hash is the JWT signature.

Pydantic schemas constrain local passwords to 12–128 characters. Public users
contain only `id`, `email`, `email_verified_at`, `created_at`, and `updated_at`.
Token pairs contain access and refresh strings, literal `"bearer"`, and positive
`expires_in`. Internal dataclasses collect service results without Pydantic
validation. SQLAlchemy models define persistence.

### `repositories/user_repository.py` and `auth_repository.py`

The user repository inserts and looks up normalized emails or IDs. The auth
repository inserts token records, locks lookup rows with `FOR UPDATE`, revokes
families, and consumes prior verification records. Inserts flush without commit.
Row locks last through the caller's transaction boundary.

A family-revocation update affects active records in one `family_id`.
Password reset instead revokes active records for all of a user's families.
Verification resend consumes all prior unused verification records before
creating a replacement.

### `services/auth_service.py` and `endpoints/auth.py`

Registration checks the normalized email, creates an Argon2id password hash,
and creates a 24-hour verification record. The route commits and refreshes the
user before email delivery. `EmailTakenError` and registration `IntegrityError`
map to `409 email_taken`. The latter currently maps any integrity error to
that response, not only unique-email errors.

Login rejects unknown or passwordless accounts with generic credentials text.
It checks `locked_until`, then the password. Invalid passwords increment the
failure count. At five failures, the service sets a 15-minute lock. The route
commits failure state before returning `401`. A locked account returns `423`.
A correct password on an unverified account returns `403`. That route rolls
back. Successful verified login clears failure state and issues a token pair.

`issue_token_pair()` creates a family UUID unless one is supplied. It signs
both JWTs, hashes the refresh `jti`, and flushes its refresh record. Rotation
validates the JWT and locks that record. It checks user, family, expiry, and
revocation, then consumes it and issues a child. Each child has a fresh expiry.
The configured refresh lifetime is per token, not an absolute family lifetime.

Reuse of a consumed record revokes the family before raising
`InvalidRefreshTokenError`. The route commits this error branch to preserve
revocation and returns `401 invalid_refresh_token`. Logout looks up the
presented refresh record and revokes its family. It returns `204`. Access JWTs
remain usable until expiry or an `auth_version` change.

Email verification locks the opaque-token record, checks expiry and prior use,
then consumes it and sets `email_verified_at` atomically. Invalid records
return `400 invalid_or_expired_token`.

Forgot-password creates a one-hour hashed reset record only for a matching
password account. Reset locks and consumes the record, changes the password,
clears lock state, increments `auth_version`, and revokes active families.
A valid reset returns `204`. Invalid reset tokens return `400`.

Resend verification is eligible only for unverified password accounts. It
consumes prior unused tokens and creates one replacement. Forgot-password and
resend commit before delivery and suppress `EmailDeliveryError`. They return
empty `202` across account states after validation and limiting. Validation,
limiter, and database failures can still prevent that response.

### `api/v1/dependencies/auth.py`

`OAuth2PasswordBearer` extracts the Bearer access token.
`get_current_user()` decodes it, loads `User` through the repository, and checks
verification and `auth_version`. Failure returns `401` with `detail`.
The configured login endpoint accepts JSON, not an OAuth2 password-form body.

The optional extractor uses `auto_error=False`. It returns `None` when it does
not extract a Bearer token, including absent or non-Bearer authorization.
A supplied invalid Bearer token still returns `401`. The URL route and limiter
share this dependency to select ownership and limit scope.

### `services/email_service.py`

The sender builds `/verify-email#token=...` or `/reset-password#token=...` from
`APP_PUBLIC_URL`. `quote()` encodes the token in the fragment. `escape()` protects
the HTML link. Fragments do not appear in normal HTTP request URLs.

An HTTPX async client sends HTML and text bodies to Resend with a five-second
timeout, Bearer API key, and idempotency key. Transport and error responses
raise `EmailDeliveryError`. Route policy decides whether that exception
propagates. Provider tests use HTTP test doubles.

## Google OIDC target and unfinished work

OpenID Connect (OIDC) sign-in is specified but not mounted. Settings,
`AuthIdentity`, and `OAuthAuthorizationRequest` are present. PKCE (Proof Key
for Code Exchange) helper work and tests are incomplete.

The target stores one authorization attempt with hashed state, nonce, verifier,
expiry, and consumption time. State must also bind to the initiating browser
session. A database lookup alone does not establish that binding. The current
design does not define its transport.

The target callback validates state, exchanges the code, validates Google's
signature and claims, then links or creates a user. For S256 PKCE, the challenge
is Base64url of SHA-256 of the ASCII verifier, without padding. The challenge
is public. The verifier remains secret until exchange.

State correlates the callback and helps resist login CSRF (cross-site request
forgery). Nonce binds an ID token to one authentication request. PKCE requires
possession of the original verifier to exchange an intercepted code. Expiry
limits abandoned requests. `consumed_at` prevents reuse of an attempt.
None of these protections is a complete implemented Google flow yet.

## Tests and verification limits

`test_health.py` uses an in-process `TestClient` and checks `200` plus the exact
health body. `test_config.py` supplies required environment variables through
`monkeypatch` and creates `Settings(_env_file=None)`. It checks values and
cache/worker defaults. Fixture cleanup restores environment variables.

`test_db_session.py` runs `SELECT 1` through `get_session()`.
Model tests inspect metadata and exercise database constraints. They create
`NullPool` engines inside each `asyncio.run()` so asyncpg connections do not
cross event loops. A connection result is not a migration-chain test.

The current categories are:

| Boundary | Existing modules and behavior |
|---|---|
| Focused unit/schema checks | `test_short_codes.py`, `test_snowflake.py`, `test_aliases.py`, `test_security.py`, auth/URL schemas, and isolated settings. They cover Base62, generator sequencing, validation, password/JWT contracts, and normalization |
| Database integration | Session connectivity, model constraints, URL/user/auth repositories, and URL/auth service workflows use real PostgreSQL. `test_models.py` also contains isolated metadata checks |
| Redis integration | `test_rate_limiter.py` uses real Redis and explicit `now_ms` to check rolling-window boundaries and separate keys |
| API/integration | `test_health.py`, `test_url_creation.py`, and `test_auth.py` drive the real FastAPI app through in-process `TestClient`. Creation/auth fixtures connect to real PostgreSQL and Redis. Cases cover HTTP outcomes, guest/user ownership, limits, local auth, refresh replay, verification, reset, and email policy |
| External-provider doubles | `test_email_service.py` replaces the HTTPX client and settings for Resend request/failure checks. Auth API fixtures replace email senders to prevent delivery |
| Unfinished helper checks | `test_oidc.py` targets PKCE helpers. `create_pkce_challenge` is absent, so these cases do not establish working Google sign-in |

`test_auth_service.py` also contains an isolated keyed-token-hash check.
Some API cases patch a limiter to raise an exception or inject an
`IntegrityError`. They test HTTP failure handling, not a real Redis outage or
a concurrent database race. No browser E2E suite exists.

API fixtures override session/client setup while retaining real dependency
behavior. The auth fixture clears its fixed limiter key before and after each
case. URL limit cases clear selected keys explicitly, but the URL fixture
does not clean every shared limiter key. Unique identifiers reduce collisions.
Some repository/service cases roll back, while API requests and seed helpers
commit rows without removing them afterward. Complete state isolation and
order independence are not established by these fixtures.

Closing a cleanup Redis client does not close the separate request client or
stop Redis. TestClient context cleanup and dependency cleanup have separate
resource responsibilities. These are current facts, not claims that the suite
satisfies every criterion in the [testing policy](../README.md#testing-policy).

See the [checklist](backend-build-checklist.md#current-verified-state) for the
latest dated full-suite result and current blockers. Use the
[development guide](development.md#tests) for commands. Historical passes do
not establish that unfinished OIDC work passes today.
